UNIT I – Overview

This unit introduces the central question of machine learning: how can a computer program improve its performance through experience? It then develops the idea of learning concepts from labelled examples and organizing possible explanations using a general-to-specific ordering.

Learning outcomes
After completing this unit, students should be able to:
  • Explain machine learning and distinguish it from conventional rule-based programming.
  • Define a well-posed learning problem using Task (T), Performance measure (P), and Experience (E).
  • Describe the major components involved in designing a learning system.
  • Differentiate supervised, unsupervised, and reinforcement learning.
  • Represent a concept-learning problem using instances, target concepts, hypotheses, and training examples.
  • Explain hypothesis spaces and the general-to-specific ordering.
  • Apply Find-S and explain version spaces and Candidate-Elimination.
  • Explain why inductive bias is required in machine learning.

Suggested teaching time: 8–10 hours (adjust according to the departmental timetable).

Prerequisites: Basic programming, data representation, elementary probability and logical reasoning.

Keywords: Experience, task, performance measure, training examples, target function, hypothesis, instance space, hypothesis space, generalization, Find-S, version space, Candidate-Elimination, inductive bias.

1. Introduction to Machine Learning

1.1 What is Machine Learning?

Machine Learning (ML) is a branch of Artificial Intelligence concerned with developing computer programs that improve their performance through experience. Instead of writing every decision rule manually, a developer supplies data or experience and chooses a learning procedure. The procedure constructs a model that can make predictions or decisions on new cases.

Tom Mitchell’s definition
A computer program is said to learn from experience E with respect to some class of tasks T and performance measure P, if its performance at tasks in T, as measured by P, improves with experience E.

Arthur Samuel described machine learning as the field of study that gives computers the ability to learn without being explicitly programmed. Both definitions emphasize improvement from experience.

1.2 Conventional programming versus machine learning

Conventional programmingMachine learning
Programmer writes explicit rules.Algorithm learns a model from examples.
Input data and rules produce output.Training data and learning algorithm produce a model; the model predicts outputs for new inputs.
Useful when rules are known and stable.Useful when patterns are complex or difficult to specify manually.
Example – Email spam detection
In a rule-based program, a programmer may manually write rules such as “if the subject contains a particular suspicious phrase, mark the email as spam.” Such rules can be brittle. In an ML approach, the system is trained on emails labelled spam or not spam. It learns statistical patterns from the examples and predicts the class of a new email. The learned model may use word frequencies, sender information and other relevant features.

1.3 How does machine learning work?

  1. Collect experience: obtain examples, observations, feedback or interaction records.
  2. Represent the problem: decide which input features and target output are relevant.
  3. Choose a learning algorithm: select a procedure suitable for the task and data.
  4. Train the model: use the experience to estimate the model parameters or rules.
  5. Evaluate: test performance on examples not used for fitting.
  6. Use and monitor: apply the model and check whether its performance remains satisfactory.

1.4 Features, need and applications

  • ML identifies patterns and relationships in data.
  • It can improve through additional relevant experience.
  • It supports prediction, classification, ranking, recommendation and decision-making.
  • It can analyze volumes of information that are difficult to inspect manually.
ApplicationPossible input dataPossible ML task
HealthcareClinical measurements, medical images, laboratory resultsRisk classification or image classification
Sports analyticsPlayer statistics, match events, fitness measurementsPerformance prediction or player grouping
BankingTransaction amount, time, location, account historyFraud detection
EducationAttendance, assessment scores, learning activityIdentify students who may need academic support

1.5 Main types of machine learning

A. Supervised learning

The learner receives labelled examples: each input is paired with its expected output. The goal is to learn a mapping from inputs to outputs.

  • Classification: predicts a category, such as spam/not spam or benign/malignant in a labelled medical dataset.
  • Regression: predicts a numerical value, such as house price or expected running time.
Sports example – Predicting match outcome
Input features might include a team's recent win percentage, home/away status and player availability. The label is the historical match outcome: win, loss or draw. A supervised classifier learns from past labelled matches. It does not guarantee the outcome of a future match; it estimates a prediction from the training patterns.

B. Unsupervised learning

The learner receives data without target labels. It attempts to discover structure, groups or useful representations in the data.

  • Clustering: groups similar examples.
  • Dimensionality reduction: represents data using fewer variables while retaining useful structure.
Healthcare example – Grouping patient profiles
A dataset containing age, blood pressure and other approved clinical measurements may be grouped to explore patterns. The algorithm is not told the correct group for each patient. The resulting clusters are exploratory patterns, not medical diagnoses.

C. Reinforcement learning

An agent interacts with an environment, takes actions and receives rewards or penalties. It learns a policy for choosing actions so as to maximize cumulative reward.

Sports example – Learning to play a game
An agent observes a game state, selects a move and receives feedback based on the outcome. Winning may provide a positive reward, losing a negative reward, and a draw a neutral reward. Through repeated play, the agent improves its action-selection strategy.
TypeTraining feedbackTypical objective
SupervisedCorrect output/label suppliedPredict the target for new inputs
UnsupervisedNo target labels suppliedDiscover structure or patterns
ReinforcementRewards or penalties from interactionLearn actions that maximize cumulative reward
Classroom check
Classify each task as supervised, unsupervised or reinforcement learning:
  1. Predicting whether an email is spam using labelled emails.
  2. Grouping customers by purchasing behaviour without preassigned groups.
  3. A game-playing agent improving through rewards after moves.
Answers: 1. Supervised; 2. Unsupervised; 3. Reinforcement.

2. Well-Posed Learning Problems

2.1 The T–P–E framework

Tom Mitchell formalizes a learning problem using three elements:

T = Task    P = Performance measure    E = Experience

A learning problem is well-posed when the task, the way performance is measured and the source of experience are clearly specified.

2.2 Example 1 – Checkers-playing program

ElementDescription
Task (T)Playing checkers.
Performance (P)Percentage of games won against opponents or in a specified tournament.
Experience (E)Practice games, including games played against itself.

Explain that “playing checkers” alone is not a complete learning-problem definition. We must also say how success is measured and what experience is available.

2.3 Example 2 – Handwriting recognition

ElementDescription
TRecognizing and classifying handwritten words in images.
PPercentage of words correctly classified.
EA collection of handwriting images with their correct transcriptions or labels.

2.4 Example 3 – Medical image classification

ElementDescription
TClassifying images into categories defined by a validated dataset, such as benign or malignant.
PAppropriate held-out evaluation measures, such as sensitivity, specificity and accuracy.
EImages with labels established through an appropriate clinical reference process.
Important distinction
A classroom ML example is not a clinical diagnostic tool. Medical predictions require validated data, careful evaluation, clinical oversight and appropriate privacy protection.

2.5 Worked exercise – Define T, P and E

Problem: A university wants to develop a model that identifies students who may need additional academic support.

  • T: Classify whether a student may need additional academic support, based on the defined target label.
  • P: Evaluate using a held-out dataset and suitable measures such as recall, precision and F1-score.
  • E: Historical, appropriately governed student records and assessment outcomes.

Discuss why attendance alone may be insufficient: the experience should represent relevant factors, and the target label must be defined carefully.

3. Designing a Learning System

Mitchell presents the design of a learning system as a sequence of important choices. The checkers example illustrates these choices.

3.1 Choosing the training experience

The training experience has a strong influence on what the learner can acquire. It should be relevant to the task and representative of the situations in which the model will be used.

Three useful considerations from the textbook discussion are:

  1. Type of feedback: direct feedback supplies the correct action or output for an individual case; indirect feedback may provide only the outcome after a sequence of actions.
  2. Degree of control: consider whether a teacher selects examples or the learner proposes cases and requests feedback.
  3. Distribution of examples: training examples should represent the situations on which performance will later be evaluated.
Checkers illustration
Direct experience: the learner is shown a board position and the correct move. Indirect experience: the learner plays a complete game and receives the final result. If the learner only plays against itself, it may fail to encounter important strategies used by strong human opponents.

3.2 Choosing the target function

The target function describes what the program must learn to predict. In the checkers example, the program can already generate legal moves; it needs to learn how desirable a board position is.

Mitchell denotes the target function by \(V:B\rightarrow R\), where \(B\) is the set of legal board states and \(R\) is the set of real-valued scores.

Board stateTarget value
Final state – win+100
Final state – loss−100
Final state – draw0
Non-final stateEstimated value based on the best final state reachable under optimal play

3.3 Choosing a representation for the target function

A simple representation is a linear combination of board features:

\(\hat V(b)=w_0+w_1x_1+w_2x_2+\cdots+w_6x_6\)

In the textbook's checkers illustration, the features include:

  • \(x_1\): number of black pieces
  • \(x_2\): number of red pieces
  • \(x_3\): number of black kings
  • \(x_4\): number of red kings
  • \(x_5\): number of black pieces threatened by red
  • \(x_6\): number of red pieces threatened by black

The weights \(w_0,w_1,\ldots,w_6\) determine the contribution of each feature. The constant \(w_0\) is the bias or additive constant.

3.4 Numerical example – Evaluating a board state

For practice, suppose a learned evaluation function has the following illustrative weights:

\(\hat V(b)=0+2x_1-2x_2+5x_3-5x_4-x_5+x_6\)

For a board with \(x_1=8,x_2=7,x_3=2,x_4=1,x_5=1,x_6=2\):

\(\hat V(b)=2(8)-2(7)+5(2)-5(1)-1+2\)
\(=16-14+10-5-1+2=8\)

The predicted board value is 8. This is an illustrative calculation to demonstrate the linear representation; the weights are not claimed to be Mitchell's trained values.

3.5 Choosing a function approximation algorithm

The learning algorithm estimates the parameters of the chosen representation from training values. One approach is to select weights that minimize squared error between target values and predictions:

\(E=\sum_i (V_{train}(b_i)-\hat V(b_i))^2\)

Mitchell discusses the Least Mean Squares (LMS) training rule as an incremental method for adjusting weights as training examples become available.

3.6 The final design – Four modules

ModuleRole in the checkers system
Performance systemPlays the game using the current learned evaluation function.
CriticExamines the game history and produces training examples or target values.
GeneralizerUses training examples to improve the estimated target function; in the example, LMS adjusts the weights.
Experiment generatorSuggests a new problem or starting situation for the performance system to explore.
Board summary – Learning system design
Training experience → Target function → Representation → Function approximation algorithm → Learned model

The four operational modules: Performance System · Critic · Generalizer · Experiment Generator.

4. Perspectives and Issues in Machine Learning

Machine learning involves several design decisions. The quality of a learned model depends not only on the algorithm but also on the training experience, target definition, feature representation and evaluation method.

4.1 Important issues to discuss

  • Choice of training data: Is it representative of future cases?
  • Quality of labels: Are the target outputs accurate and consistently assigned?
  • Feature selection: Do the chosen attributes contain useful information?
  • Generalization: Does the model perform well on unseen examples, not merely the training set?
  • Overfitting: Has the model memorized training-specific details instead of learning useful patterns?
  • Evaluation: Is the selected performance measure appropriate for the problem?
  • Ethics and privacy: Is data collected and used appropriately? Could predictions create unfair outcomes?
Cancer-classification illustration
Suppose a teaching dataset contains measurements from medical images and a target label. If nearly all training examples come from one scanner or one hospital, a model may learn scanner-specific patterns. It may perform less well on images from another source. This illustrates why representative training and independent evaluation matter. The example is for understanding ML methodology, not for clinical decision-making.

5. Concept Learning and the General-to-Specific Ordering

5.1 What is concept learning?

Much of learning involves acquiring general concepts from specific examples. Concept learning is the task of inferring a Boolean-valued function from training examples of its inputs and outputs.

A concept identifies a subset of objects or events. For example, the concept “sports days on which a person enjoys playing” divides all possible days into positive and negative examples.

5.2 The EnjoySport task (Mitchell's running example)

Mitchell uses the task of learning the days on which a person, Aldo, enjoys his favourite water sport. Each day is represented by six attributes:

AttributePossible values in the example
SkySunny, Cloudy, Rainy
AirTempWarm, Cold
HumidityNormal, High
WindStrong, Weak
WaterWarm, Cool
ForecastSame, Change

The target attribute is EnjoySport, whose value is Yes or No.

5.3 Hypothesis representation

A hypothesis is represented as a vector of six constraints, one for each attribute. A specific value means that the attribute must have that value. The symbol ? means any value is acceptable. The symbol Ø means no value is acceptable for that attribute, producing the most specific or empty hypothesis in this representation.

HypothesisMeaning
(Sunny, Warm, ?, Strong, ?, ?)Sunny days, warm air and strong wind; other attributes may take any value.
(?, ?, ?, ?, ?, ?)Most general hypothesis: every instance is classified positive.
(Ø, Ø, Ø, Ø, Ø, Ø)Most specific hypothesis: no instance is classified positive.
Important notation
A hypothesis classifies an instance as positive when the instance satisfies all constraints in the hypothesis. A positive training example has target value Yes; a negative example has target value No.

6. Formal Notation for Concept Learning

SymbolMeaning
\(X\)Set of all possible instances.
\(c\)Target concept to be learned; a Boolean function over \(X\).
\(D\)Available training examples, each represented as \((x,c(x))\).
\(H\)Set of hypotheses the learner may consider.
\(h\in H\)A candidate hypothesis.

For a Boolean concept:

\(c:X\rightarrow\{0,1\},\qquad h:X\rightarrow\{0,1\}\)

The goal is to find a hypothesis \(h\) that approximates the target concept \(c\), including on instances not present in the training data.

6.1 Instance-space calculation

In EnjoySport, Sky has 3 possible values and each of the other five attributes has 2 values. Therefore, the number of possible instances is:

\(|X|=3\times2\times2\times2\times2\times2=96\)

There are 96 possible days under this attribute representation.

6.2 Hypothesis-space calculation

For an attribute with \(k\) possible values, the hypothesis representation permits each of those values, the wildcard ?, and the most-specific constraint Ø. Therefore, the number of syntactically distinct hypotheses is:

\(|H|=(3+2)\times(2+2)^5=5\times4^5=5120\)

However, any hypothesis containing at least one Ø represents the empty set of positive instances in this conjunctive representation. Mitchell notes that the number of semantically distinct hypotheses is:

\(|H_{semantic}|=1+(3+1)(2+1)^5=1+4\times243=973\)

The count includes one empty-set hypothesis plus the non-empty conjunctions: four choices for Sky (three values or ?) and three choices for each of the other five attributes (two values or ?).

Key point
The syntactic count includes different written forms, while the semantic count merges hypotheses that make the same classification. This distinction is important when counting the hypothesis space.

6.3 Inductive learning hypothesis

The inductive learning hypothesis states that if a hypothesis approximates the target function well over a sufficiently large set of training examples, it will also approximate the target function well over other unobserved examples. This is the assumption that allows learning from a finite sample to generalize.

7. Concept Learning as Search

Concept learning can be viewed as a search through the hypothesis space \(H\). The learner examines possible hypotheses and seeks one that is consistent with the observed training examples.

7.1 Small numerical illustration

Suppose there are two attributes:

  • F1 has values A or B.
  • F2 has values X or Y.

The instance space contains:

\(X=\{(A,X),(A,Y),(B,X),(B,Y)\}\)

There are four possible instances. In a conjunctive hypothesis representation, each attribute can be constrained to one of its values or left as ?. Thus the non-empty hypotheses are:

F1 constraintF2 constraintHypothesis
AX(A, X)
AY(A, Y)
A?(A, ?)
BX(B, X)
BY(B, Y)
B?(B, ?)
?X(?, X)
?Y(?, Y)
??(?, ?)

There are nine non-empty hypotheses. Adding the single empty-set hypothesis gives ten semantically distinct hypotheses. The number of syntactic representations is \(4\times4=16\) if Ø is also allowed independently in each coordinate; several of these represent the same empty set.

Try it
If the only positive training example is (A, X), list two hypotheses that cover it. Possible answers include (A, X), (A, ?), (?, X) and (?, ?). Discuss why one example does not determine a unique target concept.

8. General-to-Specific Ordering of Hypotheses

Hypotheses can be organized according to how many instances they classify as positive. A hypothesis with fewer constraints is generally more general because it accepts more instances.

8.1 Example

Consider:

\(h_1=(Sunny, ?, ?, Strong, ?, ?)\)
\(h_2=(Sunny, ?, ?, ?, ?, ?)\)

\(h_2\) is more general than \(h_1\), because it does not require Wind = Strong. Every instance accepted by \(h_1\) is also accepted by \(h_2\), but \(h_2\) accepts additional instances.

8.2 Formal relation

We say \(h_j\) is at least as general as \(h_k\) if every instance classified positive by \(h_k\) is also classified positive by \(h_j\).

\(h_j\geq_g h_k\quad\text{if and only if}\quad\forall x\in X,\; h_k(x)=1\Rightarrow h_j(x)=1\)

The relation is a partial order: it is reflexive, antisymmetric and transitive. It is not necessarily a total order because two hypotheses may be incomparable.

Incomparable hypotheses
\(h_a=(Sunny, ?, ?, ?, ?, ?)\) and \(h_b=(?, Warm, ?, ?, ?, ?)\). One requires Sunny weather; the other requires Warm air. Some days satisfy both, but neither hypothesis includes all instances covered by the other. Therefore, neither is more general than the other.
Remember
More general = fewer restrictions = covers more instances.
More specific = more restrictions = covers fewer instances.

9. Find-S: Finding a Maximally Specific Hypothesis

9.1 Basic idea

Find-S begins with the most specific hypothesis and generalizes it only when it encounters a positive training example. It ignores negative examples.

9.2 Algorithm steps

  1. Initialize \(h\) to the most specific hypothesis.
  2. For each positive training example, compare its attribute values with the current hypothesis.
  3. If a constraint does not match the positive example, replace that constraint with ?.
  4. Ignore negative examples.
  5. Return the final hypothesis.

9.3 Worked numerical example – EnjoySport

Use the standard four-example EnjoySport training sequence discussed in Mitchell:

ExampleSkyAirTempHumidityWindWaterForecastEnjoySport
1SunnyWarmNormalStrongWarmSameYes
2SunnyWarmHighStrongWarmSameYes
3RainyColdHighStrongWarmChangeNo
4SunnyWarmHighStrongCoolChangeYes

Initialization:

\(h_0=(Ø,Ø,Ø,Ø,Ø,Ø)\)

After Example 1 (positive): replace the most-specific constraints with the values in the example.

\(h_1=(Sunny,Warm,Normal,Strong,Warm,Same)\)

After Example 2 (positive): Humidity differs (Normal versus High), so generalize that position to ?.

\(h_2=(Sunny,Warm,?,Strong,Warm,Same)\)

After Example 3 (negative): Find-S ignores negative examples. No change.

\(h_3=(Sunny,Warm,?,Strong,Warm,Same)\)

After Example 4 (positive): Water differs (Warm versus Cool), and Forecast differs (Same versus Change). Generalize both positions.

\(h_4=(Sunny,Warm,?,Strong,?,?)\)
Final Find-S hypothesis
\(\boxed{(Sunny,Warm,?,Strong,?,?)}\)
The learned hypothesis says that the positive examples observed are covered by the conditions Sunny sky, Warm air and Strong wind; humidity, water and forecast are unrestricted.

9.4 Limitations of Find-S

  • It ignores negative examples.
  • It returns one hypothesis and does not describe all consistent hypotheses.
  • It cannot determine from its output alone whether the target concept has been found.
  • It is sensitive to inconsistent or noisy positive examples.
  • It does not backtrack or maintain alternative hypotheses.
Quick question
Why does Find-S replace an attribute constraint with ? after seeing two positive examples that disagree on that attribute?
Answer: Because the final hypothesis must cover both positive examples; ? means that either attribute value is acceptable.

10. Version Spaces

10.1 Meaning

Find-S returns one hypothesis consistent with the positive examples it processes. However, many hypotheses may be consistent with all observed training examples. The version space is the set of all hypotheses in \(H\) that are consistent with the training data \(D\).

\(VS_{H,D}=\{h\in H\mid Consistent(h,D)\}\)

A hypothesis is consistent when it correctly classifies every training example in the dataset.

10.2 List-Then-Eliminate algorithm

  1. Initialize the version space with every hypothesis in \(H\).
  2. Read a training example.
  3. Remove every hypothesis that predicts a different target value from the example.
  4. Repeat for all examples.
  5. The remaining hypotheses form the version space.

This method is conceptually straightforward for a finite hypothesis space, but explicitly listing every hypothesis may be computationally expensive when \(H\) is large.

10.3 Simple worked example

Consider two binary attributes F1 ∈ {A,B} and F2 ∈ {X,Y}. Suppose the training data are:

InstanceTarget
(A, X)Positive
(A, Y)Negative

Some candidate hypotheses can be tested:

HypothesisPrediction on (A,X)Prediction on (A,Y)Consistent?

(A, ?)PositivePositiveNo
(?, X)PositiveNegativeYes
(?, ?)PositivePositiveNo
(B, X)NegativeNegativeNo

Among these candidates, (A,X) and (?,X) remain consistent. The complete version space depends on the full hypothesis representation, but this small table demonstrates the elimination process.

11. Candidate-Elimination Algorithm

11.1 Main idea

Candidate-Elimination represents the version space compactly using two boundary sets:

  • S boundary: the set of maximally specific hypotheses consistent with the training data.
  • G boundary: the set of maximally general hypotheses consistent with the training data.

All hypotheses in the version space lie between the S and G boundaries under the general-to-specific ordering.

Boundary intuition
G = general boundary (upper boundary)
All consistent hypotheses lie between G and S
S = specific boundary (lower boundary)

11.2 Initialization

\(S_0=\{(Ø,Ø,\ldots,Ø)\}\qquad G_0=\{(?,?,\ldots,?)\}\)

11.3 Processing a positive example

  • Remove from G any hypothesis that does not cover the positive example.
  • Generalize members of S minimally so that they cover the positive example.
  • Remove hypotheses from S that are more general than another member of S, and remove redundant hypotheses from G as required by the boundary representation.

11.4 Processing a negative example

  • Remove from S any hypothesis that covers the negative example.
  • Specialize members of G minimally so that they exclude the negative example while remaining at least as general as some member of S.
  • Remove redundant hypotheses from the boundaries.

11.5 Small illustrative trace

Use a two-attribute hypothesis space with F1 ∈ {A,B} and F2 ∈ {X,Y}. Begin with:

\(S_0=\{(Ø,Ø)\},\quad G_0=\{(?,?)\}\)

Example 1: (A,X) is positive. S must generalize to cover it; G already covers it.

\(S_1=\{(A,X)\},\quad G_1=\{(?,?)\}\)

Example 2: (A,Y) is negative. S=(A,X) does not cover this negative instance, so it remains. G=(?,?) covers the negative instance and must be minimally specialized. One valid specialization is (?,X); another possible specialization is (B,?). Both exclude (A,Y) and remain general enough to cover S.

\(S_2=\{(A,X)\},\quad G_2=\{(?,X),(B,?)\}\)

This example shows why Candidate-Elimination can preserve multiple possible explanations rather than selecting only one.

Assumption
Candidate-Elimination assumes that the training examples are correctly labelled and that the target concept can be represented in the chosen hypothesis space. With noisy or contradictory labels, the version space may become empty.

12. Inductive Bias

12.1 Why is inductive bias needed?

Training examples alone usually do not uniquely determine how every unseen instance should be classified. A learner therefore needs assumptions or preferences that guide generalization beyond the observed examples. These assumptions are called inductive bias.

One might try to make a learner unbiased by including every possible concept in its hypothesis space. However, a learner that has no preference among possible hypotheses cannot make useful general predictions from limited data without some assumption about which hypotheses to prefer.

12.2 Types of bias – intuitive explanation

  • Restriction/representation bias: restricts the hypotheses the learner is allowed to represent.
  • Preference bias: allows many hypotheses but prefers some over others, for example simpler hypotheses.
Example
Suppose a learner is restricted to conjunctions of attribute constraints such as (Sunny, Warm, ?, ?, ?, ?). It cannot represent every possible Boolean concept over the instance space. This is a representation restriction. A different learner may allow a larger set of hypotheses but prefer simpler ones when several fit the data.

12.3 Why bias matters

Inductive bias makes generalization possible, but it can also limit what a learner can discover. If the true concept is outside the hypothesis space, the learner cannot represent it exactly. If the bias is suitable for the problem, it can reduce search and improve generalization.

14. Unit I – Key Takeaways

  • Machine learning studies how programs improve through experience.
  • A well-posed learning problem specifies T, P and E.
  • Designing a learning system requires decisions about training experience, target function, representation and approximation algorithm.
  • Supervised learning uses labelled examples; unsupervised learning discovers structure without target labels; reinforcement learning uses rewards from interaction.
  • Concept learning infers a Boolean target concept from labelled examples.
  • The hypothesis space contains the candidate concepts the learner can represent.
  • More general hypotheses cover more instances; more specific hypotheses cover fewer.
  • Find-S generalizes from positive examples and ignores negative examples.
  • Version space contains all hypotheses consistent with the observed data.
  • Candidate-Elimination represents the version space using S and G boundaries.
  • Inductive bias provides assumptions or preferences that guide generalization.

Final teaching message
The central idea of Unit I is that a learning system uses experience to construct a model, but successful learning requires a clearly defined task, a suitable representation, representative examples and assumptions that support generalization. Concept learning makes this idea precise by searching a hypothesis space and maintaining explanations consistent with observed examples.
